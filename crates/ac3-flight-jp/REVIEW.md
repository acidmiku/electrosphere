## 5. Host-call IDs

Host-call IDs stay canonical PAL SDK addresses (the contract of the shared machine crate): the first argument of `host_call`/`host_call_result`, `match call.function` patterns, and every const used as an ID (in the crate, its unit tests or the host code) keep their PAL value. JP and PAL SDK addresses collide (JP `_card_format` 800AD808 is PAL `open`), so the tool checks that no edit touches one, and `tests/claims.rs` checks every first argument against the PAL crate.

- 38 literal IDs and 68 ID consts kept; 9 unused consts named and valued like an ID kept too.
- 26 ID consts are also used as code addresses (a dispatch arm, a comparison with a stored routine pointer): the const keeps its PAL value and those 24 uses get the JP literal in place (`/* JP NAME: */ 0x...`).
- Kept PAL by the `KEEP_PAL` list (IDs without a use that shows it): `boot.rs` RESET_CALLBACK (boot host-call ID: the PAL boot records ResetCallback as a host call), `boot.rs` CD_INIT (boot host-call ID: the PAL boot records CdInit as a host call).
- JP-native consts (already JP addresses, left as they are): `bios.rs` LSEEK 800AF3E8 (the JP resident lseek stub (BIOS B0h:33h); PAL has data there).
- IDs computed at run time (a routine pointer loaded from RAM): in the JP game these hold JP addresses, so the host must translate them to the canonical PAL ID (or the split crate must):
  - `fallback.rs:96` (PAL source): parameter `id` of `host_stub` has no traced caller fallback.rs:96
  - `sdk.rs:716` (PAL source): a computed value (`runtime_host_id...`) sdk.rs:716
  - `sdk.rs:1196` (PAL source): a computed value (`runtime_host_id...`) sdk.rs:1196
  - `sdk.rs:1788` (PAL source): a computed value (`runtime_host_id...`) sdk.rs:1788
  - `sdk.rs:1793` (PAL source): a computed value (`runtime_host_id...`) sdk.rs:1793
